## Architecture

- Server: Go 1.26+
  - Gin for HTTP routing
  - Huma v2 for REST + OpenAPI
  - coder/websocket for WebSocket
  - Bun for SQLite ORM
  - Wire for DI
- Frontend: Vue 3 SPA
  - Pinia for state
  - Panda CSS + Chakra preset for styling
  - Ark UI for headless primitives
  - vue-router for routing
  - motion-v for animation
- `apps/web/`: Vue 3 SPA frontend
- Vue components use generated styled-system JSX factories
- Vue components use generated recipes for styling
- No bespoke CSS when a Panda recipe exists

## Structure

- `apps/server/`: Go HTTP/WebSocket server
  - Gin + Huma v2 + coder/websocket + Bun + modernc.org/sqlite

- `apps/web/`: Vue 3 SPA
  - Pinia + TanStack Vue Query + Panda CSS + Chakra preset + Ark UI + vue-router
  - Dev port: 3000
- `apps/web/src/features/`: 5 feature-sliced UI modules
  - Each owns its own Pinia stores
- `apps/web/src/features/control/`: playback, control-now, floating-panel (+types)
  - UI: timeline, transport, cue tab
- `apps/web/src/features/leaderboard/`: leaderboard store
  - UI: grid/table views
- `apps/web/src/features/assets-manager/`: assets-manager store
  - UI: folder/file browser with tree view
- `apps/web/src/features/shared/`: show, realtime, confirm-action, fullscreen
  - UI: shared components
- `apps/web/src/features/extensions/`: base types + `extensionRegistry`

  - TanStack Query helpers + Valibot schemas

  - Re-exports contracts enums
  - Must not redeclare them
- Workspace packages: `@tgb-resolver/*`

## Conventions

- `verbatimModuleSyntax` root-wide
  - Use `import type` for type-only imports
- Prefer direct type annotations over `satisfies`
  - Write `const foo: readonly T[] = [...]`
  - Write `const foo: T = {...}`
  - Not `const foo = [...] satisfies T`
  - Direct annotation gives the exact type
  - `satisfies` only checks, leaves wider inferred type
  - Use `satisfies` only to preserve a narrower inferred type
- String-valued enums for domain vocabularies
  - No string unions for modes, status, event types, asset kinds
  - Contracts owns wire enums
  - realtime re-exports them
- Shortcut command system in `apps/web/src/features/shortcuts/`
  - `CommandScope` enum in `types.ts`
  - `CommandBindingKind` enum in `types.ts`
  - `scope` MUST use `CommandScope` members
  - `kind` MUST use `CommandBindingKind` members
  - Never raw string literals
  - New scope/kind requires:
    - New enum member
    - Updated `satisfies` checks in `types.ts`
    - Updated discriminated unions in `types.ts`
- Contracts build:
  - `pnpm run generate` (openapi-ts)
  - Then `tsdown`
  - Depends on current `openapi.yaml`
- OpenAPI regeneration:
  - Emitted by server `build`
  - `go run . --dump-openapi openapi.yaml`
  - Or `pnpm turbo run build --filter=@tgb-resolver/server`
- Biome v2.5.10
  - `recommended` preset
  - 100 col, 2-space
  - `organizeImports`: react-scan, blank, package, blank, alias, blank, path
  - Ignores `*.gen.ts`
- syncpack:
  - Dependency consistency
  - No explicit config file
  - Runs with defaults
- `Record<K, V>` over `Map<K, V>`
  - For immutable look-ups
  - For returned values
  - For lookup tables (`userById`, `problemById`)
  - Use `Map` only when mutability after creation is required
  - `Record` reduces GC pressure and allocations
  - `Record` is 5-10x faster for create + lookup
- Grid over Table
  - CSS Grid rows, not HTML `<table>`
  - Scopes reflows to individual rows
  - Avoids cross-cell style propagation
  - Use `gridTableTemplate()` from `apps/web/src/features/shared/ui/grid-table.ts`
  - Reference: `apps/web/src/features/control/timeline/timeline-table.vue`

### Unity FsEntry pattern (Assets Manager)

- Folders + files treated uniformly as `FsEntry`
- UNIX-style entries
- `isDirectory: boolean` discriminant
- Server mirrors this:
  - `DELETE /assets/entries/{id}`
  - `PATCH /assets/entries/{id}`
  - Body: `{ showVersion, isDirectory }`
  - Single endpoint for folders + files
- Contracts mirrors this:
  - `deleteEntryEndpoint`
  - `renameEntryEndpoint`
  - No separate folder/asset endpoints
- Client store (`assets-manager-store.ts`):
  - `selectedEntryId` navigation cursor
  - Multi-select state
  - `entries` getter merges child folders + files
  - `FsEntry` defined in `apps/web/src/features/assets-manager/types.ts`
- Views:
  - Single `EntryCard` / `EntryRow` (grid/list)
  - Single `EntryMenu` (context menu)
  - No bifurcated folder vs asset components
- Tree view:
  - `Folder` / `FolderOpen` icons
  - No chevron
  - Click toggles expand
  - `useComputed` per-node for reactive subscriptions
- Selection semantics:
  - Single-click: select / highlight
  - Double-click: navigate / open
  - Modifier + click: multi-select
  - Click outside: deselect all

### Frontend state

- Pinia setup stores with `ref` + `computed`
- Follow Vue lifecycle + rendering model
  - Use `ref` / `computed` / `watch` / `watchEffect`
  - Use template-driven rendering
  - No `createModel` / signal-as-source-of-truth
  - No `effect()`-driven DOM patching
  - No `batch()` / `peek()` helpers
  - Render reactive values in template
  - Let Vue compiler handle updates
  - Hot-path animation: imperative via `motion-v` / vanilla `motion` WAAPI in leaf components
- Vue 3.5+ primitives:
  - `useTemplateRef` for template refs
  - `defineModel` for v-model props
  - `useId` for stable ids
  - `watchPostEffect` / `watchSyncEffect` where needed
  - No deprecated callback-ref / `templateRef` workarounds
- Check VueUse first (`@vueuse/core` is a dep)
  - Prefer VueUse for debounce/throttle, storage, clipboard, visibility/resize, click-outside
  - No hand-rolled utils when a composable exists
- `@tanstack/vue-query` for server cache + mutations
- Generated `@styled-system/jsx` for layout
- Generated Chakra Panda recipes for component anatomy
- Ark UI primitives receive generated slot recipe classes
- Ark primitives do not accept styled-system layout props
- Merge overrides with Panda `cx(recipe(...), css(...))`
  - No string concatenation
  - No bespoke scoped CSS
- State styling via Panda conditionals:
  - `_hover`, `_disabled`, `_selected`, etc.
- Styling docs (read before styling work):
  - Panda CSS: https://panda-css.com/docs
  - Panda full dump: https://panda-css.com/llms-full.txt
  - Ark UI Vue: https://ark-ui.com/ (`/vue/docs`, repo `chakra-ui/ark`)
  - Chakra panda preset: `@chakra-ui/panda-preset` in `chakra-ui/chakra-ui` (`packages/panda-preset`)
- Animation:
  - `motion-v` / vanilla `motion`
  - Keep hot-path animation imperative

## Realtime contracts

- Protobuf in `apps/server/proto/show/v1/show.proto` is single source of truth
- Server broadcasts Protobuf `Envelope` over WebSocket at `/hubs/show`

### Adding a new realtime message

- Touch exactly four places, in order

1. Server Protobuf (`apps/server/proto/show/v1/show.proto`)
   - Add type to `Envelope` oneof
   - Example:
   ```protobuf
   message Envelope {
     string type = 1;
     oneof payload {
       MyNewMessage my_new_message = 8;
     }
   }
   message MyNewMessage {
     int32 show_version = 1;
     string some_data = 2;
   }
   ```
   - Run `buf generate`

2. Server Broadcast (`apps/server/features/show/*.go` or `features/realtime/orchestrator.go`)
   - Create + broadcast envelope
   - Example:
   ```go
   h.Hub.Broadcast(&showv1.Envelope{
     Type: "MyNewMessage",
     Payload: &showv1.Envelope_MyNewMessage{
       MyNewMessage: &showv1.MyNewMessage{
         ShowVersion: version,
         SomeData: "...",
       },
     },
   })
   ```

3. Client `realtime.worker.ts` (`apps/web/src/lib/realtime.worker.ts`)
   - Add case to `handleEnvelope` switch
   - Example:
   ```typescript
   case ShowMessageType.MyNewMessage: {
     if (payload.case !== "myNewMessage") return;
     post({
       type: RealtimeWorkerResponseType.Message,
       message: {
         type: ShowMessageType.MyNewMessage,
         showVersion: payload.value.showVersion,
         someData: payload.value.someData,
       },
     });
     break;
   }
   ```
   - Add wire-to-enum mapping in `ws-client.ts` `wireToMessageType`

4. Client `realtime-handler.ts` (`apps/web/src/features/control/realtime-handler.ts`)
   - Handle type in `if` chain inside `applyControlRealtimeMessage`

### Verification rules

- Every `Envelope` payload variant has a case in `realtime.worker.ts` `handleEnvelope`
- Every handled message produces a `ShowWebSocketMessage` variant in `packages/realtime/src/types.ts`
- Every `ShowWebSocketMessage` variant is handled in `applyControlRealtimeMessage`
